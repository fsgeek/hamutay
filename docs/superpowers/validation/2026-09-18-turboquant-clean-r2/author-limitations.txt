- The public interface contract mentions adapter functions `verify_pinned_checkout`, `preflight_author_qjl`, and `run_author_qjl_differential` but explicitly omits their import module path (unlike Tasks 1-5 which explicitly list `hamutay.turboquant.*`). Therefore, direct unit testing of these Python functions is omitted to avoid guessing undocumented behavior. Validation is appropriately restricted to their fully documented CLI counterpart `scripts/turboquant/author_qjl_oracle.py` alongside the main CLI's handling of the generated artifacts.
- Tests involving CLI execution with `main()` use mock patches for heavy internal worker functions (`run_registered_workers`) because executing actual registered worker paths without a GPU and full dataset in a unit-test context would hang or fail spuriously. This design respects the instruction that "GPU acquisition is external; tests must not change services or lease state".
- The requirement that "QJL projections are stored as rows, so a batch sketch is residual @ projection.T" implies specific orientation inside `estimate_inner_products`. This is tested via basic shape-compatibility boundaries as documented by the signature, but explicit mathematical verification of the dot product is deferred to integration testing due to lack of exposed private helpers.
