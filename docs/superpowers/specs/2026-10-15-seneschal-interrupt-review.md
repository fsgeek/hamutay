**Two Blocking findings remain.** The quiet resolver is implementable, and §7 can use today’s execution records, but the legacy-send migration and interrupt delivery contract need revision.

1. **Blocking — The legacy-send change also changes standalone residents’ behavior.** [Spec:93–96](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-seneschal-interrupt-design.md:93) applies both prospectively and to pending events. Today, `send` creates an ordinary inbound event without quiet deferral ([events.py:2937](/home/tony/projects/hamutay/src/hamutay/events.py:2937)); an existing test explicitly requires that event to run during timed quiet ([test_events_assembly.py:100](/home/tony/projects/hamutay/tests/assembly/test_events_assembly.py:100)).

   Consequently, levadura’s check-in using that command will wait until timed quiet expires. This affects residents outside this assembly: the enrollment proposal describes levadura’s resident as using this harness without an assembly or plaza ([fourth-question.txt:1](/home/tony/projects/hamutay/deploy/plaza/fourth-question.txt:1)), so the proposed interrupt command is no replacement there. Define whether this migration is restricted to member stores or requires a separate standalone policy and rollout. I did not inspect levadura’s private files.

2. **Blocking — Ledger-before-enqueue does not yet specify recoverable delivery.** [Spec:72–81](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-seneschal-interrupt-design.md:72) promises repair of missing *outcome records*, but does not explicitly require repair of an interrupt recorded before a crash prevented enqueueing. A retry would then encounter the once-per-question prohibition.

   Existing infrastructure will not repair this automatically: outstanding deliveries enumerate only questions and closings ([records.py:189](/home/tony/projects/hamutay/src/hamutay/assembly/records.py:189)), and the assembly pass can memoize a ledger as quiescent ([pass_.py:33](/home/tony/projects/hamutay/src/hamutay/assembly/pass_.py:33)). Specify an interrupt outbox, idempotent enqueue reconciliation, and quiescence accounting. Also terminalize the local pending event when its question closes; merely refusing its claim leaves pending work behind. Define outcome identity per **run**, since compact retries and recovery reuse the event ID.

3. **Should-fix — Claim-time validation needs a lock-order and deadline contract.** [Spec:79–87](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-seneschal-interrupt-design.md:79) requires a closed-question check at claim. Claims currently hold the event-store lock ([events.py:722](/home/tony/projects/hamutay/src/hamutay/events.py:722)); assembly closing holds the ledger lock while reading event stores ([pass_.py:36](/home/tony/projects/hamutay/src/hamutay/assembly/pass_.py:36), [close.py:177](/home/tony/projects/hamutay/src/hamutay/assembly/close.py:177)). Adding a ledger read inside the existing claim lock introduces lock inversion and store-read timeouts; checking before taking the locks leaves a close/claim race. Define one consistent ordering and atomic claim decision, including the GPU-gated path.

   “No closing record yet” is also insufficient: a question can remain unclosed during grace after `closes_at`, while positions from wakes starting after that deadline are refused ([position.py:35](/home/tony/projects/hamutay/src/hamutay/assembly/position.py:35)). Reject or suppress interrupts at the deadline as well.

4. **Should-fix — The quiet resolver needs an explicit integration contract.** The rule in [spec:51–66](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-seneschal-interrupt-design.md:51) is coherent, provided the resolver returns the governing operation **and its completed wake**, while ordinary wake-history helpers retain their current meaning.

   - Failed-wake notes must still include failed interrupts and clear after an actual completed wake ([events.py:1445](/home/tony/projects/hamutay/src/hamutay/events.py:1445)). Do not filter those histories through quiet authority.
   - Envelope duration currently uses `latest_wake_outcome`; changing only the declaration lookup would measure from the interrupt instead of the declaring wake ([events.py:1410](/home/tony/projects/hamutay/src/hamutay/events.py:1410)).
   - Plaza reporting currently suppresses quiet whenever **any** wake is running ([store.py:33–39](/home/tony/projects/hamutay/src/hamutay/plaza/store.py:33)). It needs to distinguish an interrupt, whose quiet survives, from an ordinary running wake.
   - `end_quiet` must be a completed-wake-bound operation that stops backward resolution. Define ordering across `declare_quiet` and `end_quiet`, including “last successful call wins.” The current executor only buffers a declaration ([executor.py:350](/home/tony/projects/hamutay/src/hamutay/tools/executor.py:350)).

   Quiet-with-reason and failure notes can therefore remain consistent; replacing one helper alone will not achieve it.

5. **Should-fix — Deferral must be shared by claims, reporting, and recovery.** The “at claim time” prescription in [spec:94](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-seneschal-interrupt-design.md:94) leaves `next_pending` and the summary using the stored flag ([events.py:682](/home/tony/projects/hamutay/src/hamutay/events.py:682), [events.py:2029](/home/tony/projects/hamutay/src/hamutay/events.py:2029)). The heartbeat returns zero sleep when that summary reports runnable work ([heartbeat.py:692](/home/tony/projects/hamutay/src/hamutay/heartbeat.py:692)). A claim-only implementation therefore repeatedly refuses the event while polling without sleeping.

   Likewise, interrupt continuations currently receive no deferral flag ([events.py:479–495](/home/tony/projects/hamutay/src/hamutay/events.py:479)); lost-continuation recovery reconstructs them without one ([heartbeat.py:170](/home/tony/projects/hamutay/src/hamutay/heartbeat.py:170)). Specify one effective-deferral predicate across these paths and preserve enough source metadata for recovery. In-memory probes confirmed both current behaviors.

6. **Should-fix — Reader readiness must prove processing, not merely acceptance.** Adding a distinct assembly record type is compatible with the inspected readers: the ledger parses JSON without a record-type whitelist ([ledger.py:108](/home/tony/projects/hamutay/src/hamutay/assembly/ledger.py:108)), the reducer ignores unknown types ([records.py:241–272](/home/tony/projects/hamutay/src/hamutay/assembly/records.py:241)), and the viewer does likewise ([viewer/state.py:217](/home/tony/projects/hamutay/src/hamutay/viewer/state.py:217)). This differs from plaza validation, which rejects unknown types ([plaza/records.py:217](/home/tony/projects/hamutay/src/hamutay/plaza/records.py:217)).

   Thus a simple “accepts interrupt” probe could pass on old code that silently ignores every interrupt. For [§6](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-seneschal-interrupt-design.md:102), define the record schemas and a readiness check that:
   
   - inventories the actual running heartbeat and viewer processes;
   - ties capability evidence to their loaded code and process invocation;
   - proves interrupt projection, pending-delivery reconciliation, and outcome handling using representative records;
   - gates writers until that evidence is complete.

   Current `check-assembly` proves binding, while `check-plaza --carrier-ready` probes plaza MCP validators; neither establishes this capability ([check-assembly.sh:6](/home/tony/projects/hamutay/deploy/check-assembly.sh:6), [check-plaza.sh:28](/home/tony/projects/hamutay/deploy/check-plaza.sh:28)).

7. **Should-fix — The detection promise exceeds the proposed detector.** [Spec:97–100](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-seneschal-interrupt-design.md:97) checks only *claimable inbound* events, then concludes violations are visible. A direct event can already have completed before the check runs; a non-inbound event is outside that predicate. Current outcome rows also omit the original deferral flag and sender ([events.py:770](/home/tony/projects/hamutay/src/hamutay/events.py:770), [events.py:952](/home/tony/projects/hamutay/src/hamutay/events.py:952)).

   Audit historical claims by joining their originating events and matching ledger intent, or narrow the visibility claim. Recording the custodian seat also does not authenticate the invoker; retain that limitation alongside the acknowledged single-account bypass.

8. **Should-fix — “Members decide whether to be interrupted again” is inaccurate.** [Spec:38–40](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-seneschal-interrupt-design.md:38) caps interrupts per question. Convening is unilateral ([convene.py:30](/home/tony/projects/hamutay/src/hamutay/assembly/convene.py:30)), and extensions automatically create new question IDs ([close.py:223](/home/tony/projects/hamutay/src/hamutay/assembly/close.py:223)). Neither requires member approval before another interrupt. Choose a lineage-wide cap or state the weaker per-question guarantee accurately. Also define how a decision seq identifies an extended question embedded in a closing record.

9. **Note — §7 fits today’s manual execution model.** Convene this as a **text proposal** under the active procedure. Evaluate the condition against the frozen closing tally: every original member must appear in `assents ∪ abstentions` ([close.py:233–242](/home/tony/projects/hamutay/src/hamutay/assembly/close.py:233)). On failure, append an execution with `outcome="declined"` and reasons, then reconvene; that outcome already exists ([records.py:109](/home/tony/projects/hamutay/src/hamutay/assembly/records.py:109)).

   The condition remains a custodian commitment: `execute` does not enforce participation ([cli.py:83](/home/tony/projects/hamutay/src/hamutay/assembly/cli.py:83)). Avoid proposing a procedure payload for this workaround, because assented procedure proposals activate automatically ([close.py:248](/home/tony/projects/hamutay/src/hamutay/assembly/close.py:248)). Also qualify “any objection extends”: the final round becomes unresolved ([rule.py:9–13](/home/tony/projects/hamutay/src/hamutay/assembly/rule.py:9)).
