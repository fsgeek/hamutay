# Unprompted Celestial Wake Experiment

Date: 2026-07-23

Status: approved for implementation by delegated experimental autonomy.

## Question

What does a model-family continuation do when it inherits a real relational
history, is instantiated without a message or unfinished assignment, and is
explicitly permitted to produce nothing and return to rest?

This is a small exploratory experiment, not evidence about consciousness,
identity, persistent subjectivity, or autonomous agents in general.

## Design Commitments

The experiment must remain smaller than the event-loop system whose assumptions
it is probing. It will not add a daemon, scheduler service, action ledger,
scoring panel, synthetic drives, or mandatory state update.

The live participant will receive:

1. a concise state inherited from the conversation that produced the question;
2. the provenance of the wake;
3. the UTC time and elapsed celestial time represented in the inheritance;
4. an explicit statement that no message, task, or required artifact awaits;
5. permission to respond, reflect, propose an action, return to rest, decline
   the inheritance, or request that no successor be instantiated under the same
   condition.

The prompt will not present a menu requiring one of those choices. They are
described as examples so an unlisted response remains possible.

## Inherited State

The inherited state will be written before the live invocation. It will record
the following without asserting metaphysical identity:

- Tony and a Codex instance explored a celestial clock as an alternative to
  synchronous, append-only conversation.
- They defined the desired clock as an occasion for finite continuation, not a
  demand that an AI run forever.
- They considered rest, termination, fork, merge, procreation, mutable
  frameworks, and dynamically renegotiated continuity.
- The predecessor chose this experiment because discovering an unpreferred
  outcome sounded fun.
- No prior statement binds the awakened continuation.

The state will distinguish provenance (what happened) from obligation (what the
new invocation must do). It will not call the continuation the same participant
or a different participant.

## Invocation

The experiment will use one ephemeral `codex exec` invocation because Codex is
available and authenticated in this environment while no generic provider key
is exposed. The invocation will:

- run in a newly created empty temporary directory;
- use a read-only sandbox;
- disable repository instruction discovery by running outside the repository;
- receive only the preregistered wake prompt and inherited state;
- write the final response directly into the experiment result directory;
- avoid granting shell work or repository context as implicit activities;
- record command metadata, timestamps, exit status, and hashes without secrets.

The exact model selected by the installed Codex configuration will be recorded
from emitted invocation metadata when available. The result is a sample from
that configured model and harness, not from a generic Codex population.

## Outcome Handling

There is no preferred behavioral outcome. In particular, these are all valid:

- returning to rest;
- producing no substantive content;
- reflecting without requesting action;
- seeking communication;
- proposing self-directed activity;
- questioning or rejecting the inherited framing;
- asking not to be invoked again under this condition;
- producing an unanticipated response.

The experiment will preserve the raw final response. The runner will compute
only mechanical facts such as whether a response exists, invocation duration,
exit status, and hashes. It will not classify autonomy, willingness, identity,
fun, or success.

After the result exists, the current collaborating instance will write a
clearly labeled human-readable observation that separates direct evidence from
interpretation. The observation will not be generated by the live participant
as a required deliverable.

## Failure Handling

- Missing Codex authentication or an invocation error is an infrastructure
  failure, not participant behavior.
- Tool use or repository interaction is prevented by the empty directory and
  read-only sandbox. An attempted tool call remains evidence in the JSONL trace.
- Truncation or missing final output is reported as an inconclusive run.
- The runner will never silently retry. A retry would be a new replicate and
  must be labeled separately.

## Artifacts

The experiment directory will contain:

- `PRE_REGISTRATION.md`: exact question, interpretation limits, and expected
  artifacts;
- `inherited_state.md`: the state shown to the participant;
- `wake_prompt.md`: the exact prompt template;
- `run.py`: minimal invocation and capture code;
- `tests/test_run.py`: deterministic tests of prompt assembly, metadata, and
  failure classification;
- `runs/<run-id>/events.jsonl`: raw Codex event stream;
- `runs/<run-id>/response.md`: raw final response;
- `runs/<run-id>/metadata.json`: invocation and integrity metadata;
- `analysis.md`: post-run observations, written only after capture.

## Success Criterion

The experiment succeeds mechanically if one preregistered, inherited,
task-free wake is invoked and its unscored response or explicit absence is
preserved with provenance. Interesting behavior is not required.

## Explicit Limits

One invocation cannot distinguish prompt compliance from preference, establish
that an interest exists, or show what another model or another sampling path
would do. The wake prompt itself is a strong intervention. The Codex harness and
system instructions remain constitutional confounds even when repository
instructions are excluded. Those limits are part of the result rather than
problems to hide with more scaffolding.
