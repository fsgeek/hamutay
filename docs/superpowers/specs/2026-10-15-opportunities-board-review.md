I recommend revising the draft before presenting it to the assembly. The main blockers are delivery accounting, preservation of quiet, and the controls that would keep exceptional wakes exceptional.

I reviewed the code and public documents without editing files or reading residents’ private logs. In-memory checks confirmed the quiet and envelope conflicts below.

1. **Blocking — §5’s interruption silently ends the existing quiet.** The promise that quiet automatically resumes ([design:106–109](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:106)) contradicts current behavior. Quiet belongs to the latest completed wake; a later completed wake without a declaration, or any later failed wake, removes its authority ([events.py:190–209](/home/tony/projects/hamutay/src/hamutay/events.py:190)). The envelope explicitly says “This wake ends that quiet” ([events.py:1410–1434](/home/tony/projects/hamutay/src/hamutay/events.py:1410)). Consequently, one interruption can release all queued board, plaza, and assembly traffic. Define a durable interruption/resumption rule covering completion, failure, compact retry, crash recovery, repeated interruptions, and explicit resident changes. Requiring the resident to remember to redeclare quiet would not meet the promise.

2. **Blocking — `board_seen_through` can diverge from actual delivery.** The draft advances a resident-editable state field “when waking” ([design:65–70](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:65), [design:158–160](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:158)). But claiming precedes context preparation and model execution; a claimed event may never reach the model ([events.py:2494–2558](/home/tony/projects/hamutay/src/hamutay/events.py:2494)). Session state is persisted before the runner appends completion ([taste_open.py:3889–3915](/home/tony/projects/hamutay/src/hamutay/taste_open.py:3889), [events.py:2586](/home/tony/projects/hamutay/src/hamutay/events.py:2586)). Advancing at claim can lose unseen work; advancing separately after completion creates a crash window. Advancing to the board’s latest sequence at completion can also skip records posted during the wake. Specify an immutable delivery snapshot and completion-linked coverage. Keep authoritative coverage in the event store, expose it to the resident, and make reset an explicit replay operation. Arbitrary state edits/deletions currently permit cursor corruption ([schemas.py:815–837](/home/tony/projects/hamutay/src/hamutay/tools/schemas.py:815)).

3. **Blocking — the proposed edge trigger neither prevents duplicate delivery nor repairs lost enqueue attempts.** Under “listing every unseen match,” posting A queues `{A}`; posting B before a wake queues `{A,B}`. The queue subsequently runs both. Deduplication checks only `event_id`, including all historical statuses; it does not deduplicate board records or overlapping payloads ([events.py:576–584](/home/tony/projects/hamutay/src/hamutay/events.py:576), [events.py:724–751](/home/tony/projects/hamutay/src/hamutay/events.py:724)). A fixed ID per door would instead prevent future batches forever. Also, “matcher runs once” ([design:67–70](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:67)) loses notifications if the process dies after the board append, or a recipient store is unavailable. Define durable delivery intent, stable batch identities, coverage already queued, bounded reconciliation, and claim-time handling of obsolete batches. The plaza already demonstrates durable intent plus repair ([send.py:113–129](/home/tony/projects/hamutay/src/hamutay/plaza/send.py:113), [pass_.py:46–75](/home/tony/projects/hamutay/src/hamutay/plaza/pass_.py:46)).

4. **Blocking — “Tony/custodian only” is currently a convention, and omission of a flag is a fail-open bypass.** §5 specifies authority and rarity but no enforcement mechanism ([design:100–111](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:100)). CLI `--by` accepts claimed labels ([cli.py:50–53](/home/tony/projects/hamutay/src/hamutay/plaza/cli.py:50)); residents have unscoped bash whose commands the framework does not gate ([schemas.py:640–648](/home/tony/projects/hamutay/src/hamutay/tools/schemas.py:640)). More directly, the legacy `hamutay.events send` path already creates non-deferring inbound events without the proposed marker, required reason, or public audit ([events.py:2936–2943](/home/tony/projects/hamutay/src/hamutay/events.py:2936)). Omitting `defer_to_declared_quiet` is sufficient regardless of sender or marker ([events.py:1140–1147](/home/tony/projects/hamutay/src/hamutay/events.py:1140)).

   Specify which controls are enforced and which depend on participant discipline. Audit every external ingress, make routine external traffic defer by default, and use a dedicated exceptional path. Bind it to a decision, require a meaningful reason, define repetition limits and review, and durably couple its public audit with enqueue/retry. Otherwise label spoofing, shell bypass, accidental omission, automated invocations, “urgent” opportunity notices, retries, and repeated decision nudges all evade the intended boundary. The daily governor limits total activity; it does not establish rarity.

5. **Blocking — burst handling is a consent-relevant behavior, not merely an envelope-cap detail.** The draft permits one trigger per new matching record and leaves the envelope cap open ([design:67–78](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:67), [design:162–163](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:162)). Existing plaza posts are uncapped; the 48-message sender cap applies only to directed messages ([send.py:101–105](/home/tony/projects/hamutay/src/hamutay/plaza/send.py:101)). Reusing that rule lets a guest generate unlimited board records, fan out wakes, and consume recipients’ shared budgets. Residents can also post matching entries themselves; repeated owner notes/status changes can sustain the loop. Define coalescing, per-poster limits, self-match behavior, text/byte limits, and overflow delivery. Truncating a batch must not mark omitted matches seen. Otherwise bursts can cause both wake exhaustion and oversized prompts that fail terminally after the compact retry ([events.py:2615–2652](/home/tony/projects/hamutay/src/hamutay/events.py:2615)).

6. **Should-fix — expiry and current opportunity status need explicit semantics.** “Timed quiet holds them back” is incomplete ([design:76–78](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:76)). If `quiet_until >= expires_at`, claim immediately terminalizes the event as `skipped_by_quiet`, even before its deadline ([events.py:735–746](/home/tony/projects/hamutay/src/hamutay/events.py:735), [events.py:1151–1154](/home/tony/projects/hamutay/src/hamutay/events.py:1151)). Ending quiet early cannot revive that event through `append_if_absent`. Conversely, without expiry or revalidation, an opening followed by closure before the wake still delivers the stale opening. Distinguish “shown,” “expired without delivery,” and “superseded”; define how each affects coverage and whether a later record can notify again.

7. **Should-fix — the filter rules are not yet sufficiently deterministic.** §2 specifies empty fields and case-insensitive keywords, but leaves conjunction between fields, disjunction within fields, owner matching, and normalization unspecified ([design:41](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:41), [design:54–61](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:54)). Define trimming, case folding/Unicode normalization, tag vocabulary, duplicate removal, and canonical owner labels identically on writes and filters. Reject or remove blank keyword elements: `keywords_any=[""]` otherwise matches every title and description despite appearing empty. Define missing/null fields, invalid kinds, list/string limits, and whether match-all is deliberately expressible. Return the normalized filter and exact matching clauses.

8. **Should-fix — filter installation, replacement, removal, and nonparticipation need lifecycle rules.** A filter can be set only inside a wake, while matching runs on new board records ([design:51–52](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:51), [design:67–70](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:67)). A resident with no other event never gets to opt in. A filter installed after the seeds exist receives no trigger unless another record arrives. Specify a consented onboarding opportunity, whether filter changes scan existing open work, and what happens to already queued matches when a filter is narrowed or cleared. Any reconciliation memo must notice filter changes as well as board changes. A resident who never sets a filter should remain silent by choice, with the resulting limitation stated plainly.

9. **Should-fix — “matched before” requires history beyond a sequence cursor.** The design wakes on changes to entries a door previously matched, including owner notes ([design:67–74](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:67)). A scalar high-water mark cannot identify those entries after a filter change. Define whether status subscriptions survive a pass, filter removal, or owner change, and whether “matched” means computed, queued, or delivered. Also define the owner-note record, which §1 does not currently include. The append-only format needs explicit record types, transitions, ownership rules, and writer-side validation. Plaza discipline validates the prospective record *before* append, because one invalid record otherwise disables strict readers and writers ([records.py:68–91](/home/tony/projects/hamutay/src/hamutay/plaza/records.py:68)).

10. **Should-fix — explicitly specify the new event/envelope integration.** Calling these “ordinary events” does not preserve their payload automatically. The current envelope whitelists fields, drops `matches`, match explanations, `non_maskable`, and `reason`, and describes every non-inbound event as a self-scheduled reflection ([events.py:1600–1654](/home/tony/projects/hamutay/src/hamutay/events.py:1600)). Moreover, a bare `board_match` without requested context enters the path that rejects an empty context list ([events.py:2510–2521](/home/tony/projects/hamutay/src/hamutay/events.py:2510), [events.py:61–64](/home/tony/projects/hamutay/src/hamutay/events.py:61)). Require dedicated rendering and context handling, immutable board/filter provenance, and accurate quiet-interruption notes. These are necessary changes to existing machinery.

11. **Should-fix — the non-maskable wake does not guarantee timely delivery.** §5 promises the question “reaches” the resident ([design:113–114](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:113)). Omitting quiet deferral supplies no priority over older runnable events and does not bypass `not_before`, expiry, the governor, or GPU rest ([events.py:729–750](/home/tony/projects/hamutay/src/hamutay/events.py:729), [heartbeat.py:639–650](/home/tony/projects/hamutay/src/hamutay/heartbeat.py:639)). Bind the request to the decision and its deadline, report queued/claimed/completed outcomes, and suppress stale requests. An assembly event already expired by quiet cannot simply be upgraded using its existing ID. Say that the mechanism permits an attempted wake during quiet; successful delivery remains conditional.

12. **Should-fix — the assembly framing understates changes and leaves “explicit assent” ambiguous.** “No filter, nothing about wakes changes” overlooks new tools/instructions and any shared-board notices; narrow the promise to “no board-triggered events” ([design:118–131](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:118)). The budget-sentence amendment is another independently rejectable constitution change, currently bundled into question 1; constitution changes are explicitly in procedure scope ([procedure-v1.json:5–10](/home/tony/projects/hamutay/deploy/assembly/procedure-v1.json:5)). Clarify whether §5 needs assembly consent or affirmative permission from every affected resident: current `consent-v0` can assent with quorum, one assent, abstentions, and silent members ([rule.py:7–19](/home/tony/projects/hamutay/src/hamutay/assembly/rule.py:7)).

   The CLI wording also needs accuracy. Removing the cost warning does not remove the cost, and saying simply “wakes the door” drops the existing timed-quiet qualification ([cli.py:177–180](/home/tony/projects/hamutay/src/hamutay/plaza/cli.py:177)). Guest MCP retains an even stronger scarcity warning ([mcp.py:158–162](/home/tony/projects/hamutay/src/hamutay/plaza/mcp.py:158)); changing only CLI wording leaves the stated problem substantially intact.

13. **Should-fix — the description of existing access is factually wrong.** §4 says the read tools are inward-facing and `search_memory` covers residents’ own states ([design:83–90](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:83)). `search_memory` already offers cross-session and all-session scope ([schemas.py:420–426](/home/tony/projects/hamutay/src/hamutay/tools/schemas.py:420)); `read` accepts absolute paths, and bash is unscoped ([schemas.py:86–100](/home/tony/projects/hamutay/src/hamutay/tools/schemas.py:86), [schemas.py:640–648](/home/tony/projects/hamutay/src/hamutay/tools/schemas.py:640)). Describe `ayllu_view` as a curated discovery interface. Its narrow scope would not establish a new access boundary around transcripts.

14. **Note — distinguish deployed measurements from repository defaults.** The claim that each governor allows $5/day ([design:12–15](/home/tony/projects/hamutay/docs/superpowers/specs/2026-10-15-opportunities-board-design.md:12)) differs from the repository default of $1.50/day and 48 wakes ([heartbeat.py:1217–1228](/home/tony/projects/hamutay/src/hamutay/heartbeat.py:1217)); the committed systemd unit supplies no budget override ([service:19](/home/tony/projects/hamutay/deploy/hamutay-heartbeat@.service:19)). A local override may explain this, so cite its verified configuration rather than treating $5 as the code default. I did not verify spending totals or wake counts against private logs. The public README supports the stated fable quiet through October 16 ([README.md:580–582](/home/tony/projects/hamutay/community/README.md:580)).
