# Camera Source B r1: Codex review, round one (2026-11-04)

Read-only review of `2026-11-04-camera-source-b-design.md` r1 (f7b346f), copied verbatim from its report. r2 answers it.

**Blocking findings remain.** References below use [r1](/home/tony/projects/hamutay/docs/superpowers/specs/2026-11-04-camera-source-b-design.md).

1. **Blocking — “Never contents” is already violated by the raw log.** B2 says query text is never stored, but Facts 2 and B5–B6 explicitly write full queries to disk, including excluded databases’ queries and writes. A query containing private text persists until deletion. **Additional hypothesis:** a scribe crash dump could preserve its raw input buffer; the [service unit](/home/tony/projects/hamutay/deploy/camera/hamutay-camera-scribe.service:9) specifies no dump protection. Narrow the promise explicitly and define logging/dump restrictions. *(r1 L18–22, L38–55.)*

2. **Blocking — EOF does not mean a rotated file is finished.** Between rename and completed HUP handling, the scribe can reach EOF and unlink the file while arangod still holds it open. Subsequent writes disappear into the unlinked inode; a failed HUP can prolong this indefinitely. Fact 5 proves successful reopening, not a safe handoff protocol. Require a sealed-file acknowledgement before deletion. *(B6, L51–55; Fact 5, L25–26.)*

3. **Blocking — Offset persistence is not coupled to durable output.** Advancing B7’s offset before buffered records are inserted/spooled loses them on crash; storing output before advancing the offset permits duplicates. Existing [Scribe.put()](/home/tony/projects/hamutay/src/hamutay/camera_scribe.py:106) assigns fresh UUIDs, so rereading audit lines defeats spool conflict deduplication. Following the live inode and later rereading its renamed path can also duplicate its prefix. Specify durable checkpoint ordering and stable source identities. *(B4/B6/B7, L44–60.)*

4. **Blocking — Rollback instructs restoration that can destroy committed writes.** Both containers use the same existing volume; restarting the old container does not inherently discard intervening writes. Restoring the step-2 backup does. Moreover, backup precedes “doors idle,” which neither prevents new events nor quiesces other writers. A failed verification after new persistence could therefore trigger data loss. Define quiescence and separate container rollback from destructive data recovery. *(Cutover L76–85.)*

5. **Significant — Rotation provides no capacity bound.** With the scribe down for hours, the timer keeps accumulating raw files; deletion depends entirely on scribe recovery. B8’s 1 MB parser limit does not bound files written by arangod. A sustained query workload can exhaust the audit filesystem—and production storage if shared. Require capacity limits, independent monitoring, and an explicit overflow policy. *(B5–B8, L48–63.)*

6. **Significant — Header delimiters can defeat database filtering under unproven conditions.** A synthetic database name `apacheta | local | http basic | query document | PRIVATE | tail` makes the prescribed split report database `apacheta`, operation `query document`, result `PRIVATE`. **Hypothesis:** this reaches production if extended names are enabled and audit output leaves pipes unescaped; neither fact is probed. [Extended naming rules permit these characters](https://docs.arango.ai/arangodb/3.12/concepts/data-structure/databases/). Query-text pipes alone stay in field ten and cannot shift B1/B3. *(Facts 3, B1/B3/B8, L20–22, L33–43, L61–63.)*

7. **Significant — The existing sandbox prevents the promised purge.** The scribe has `ProtectSystem=strict`, with writable state/runtime directories but no exception for `/var/lib/hamutay-camera-audit`. Group permissions in B5 do not override that [read-only namespace](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec). Deletion fails after ingestion, leaving raw contents indefinitely unless the unit changes. *(B5/B6; [unit L13–23](/home/tony/projects/hamutay/deploy/camera/hamutay-camera-scribe.service:13).)*

8. **Significant — Cutover does not establish endpoint identity.** [Plaza seq 116](/home/tony/projects/hamutay/community/plaza/plaza.jsonl:116) reports wrong-server forwarding despite correct Docker inspection results. The [backup script](/home/tony/projects/hamutay/deploy/backup-arango.sh:57) obtains counts through the host port but dumps inside the named container. Thus `ok` and count agreement do not establish that clients, counts, and dump reach the same server. Require identity checks before backup, after recreation, and after rollback. *(Cutover L76–85.)*

9. **Significant — Recreation and rollback lack a complete executable contract.** “Same image, volume, port and restart policy” plus recorded inspection does not specify reconstruction of entrypoint/Cmd, environment, every mount, networks, binding addresses, or other effective settings. Omitting one can break production startup. Rollback also omits restoring the disabled restart policy, restoring the original container name used by backup/rotation, and explicitly restarting the scribe. *(Cutover L77–85; backup script L18.)*

10. **Significant — Catch-up can damage Source A’s recording.** **Integration hypothesis:** draining hours of audit backlog through the existing single-threaded scribe without work budgets delays socket reception. Its [storage calls](/home/tony/projects/hamutay/src/hamutay/camera_scribe.py:106) can block five seconds each; both sources would also compete for the same 256 MB spool. Source B recovery can therefore cause Source A drops or consume its remaining spool capacity. Specify fairness, bounds, and exhaustion accounting. *(B6/B7; existing main loop L242–269.)*

11. **Significant — “Every read” exceeds the demonstrated coverage.** B9 enables queued auditing, whose [documented behavior permits crash/power-loss loss](https://docs.arango.ai/arangodb/3.12/components/arangodb-server/options/). B7’s ten-minute silence check cannot detect a lost batch followed promptly by normal traffic. **Further hypothesis requiring a probe:** write-only AQL is also labelled `query document`, contradicting B1’s exclusion of writes. State observable coverage and loss limits explicitly. *(B1/B7/B9, L33–37, L56–66.)*

12. **Minor — Attribution is honest internally; acceptance criteria remain incomplete.** Fact 4 correctly limits attribution to database users, but should explicitly repeat the probe’s shared-account warning in user-facing output: two residents sharing credentials remain indistinguishable. B9 also supplies neither reproducible workloads nor an acceptable latency threshold; an arbitrarily large slowdown still satisfies “record both.” *(Facts L23–24; B9 L64–66; [probe L15–17](/home/tony/projects/hamutay/docs/superpowers/specs/2026-11-04-camera-source-b-probe.md:15).)*
