# Decisions left open by camera r6

These tests were written against `docs/superpowers/specs/2026-11-03-access-camera-design.md`
and all four adjacent reviews, before any camera implementation existed. The
following are harness choices or interpretations, not additional implementation
requirements hidden in the tests. Line numbers refer to that r6 spec.

| Spec quote | Choice made by these tests |
| --- | --- |
| L174: “Times are timezone-aware `datetime` in UTC.” L56: “ISO 8601 UTC, microseconds” | In-memory messages, records and status helper results use `datetime`; `encode_message` serializes timestamps. Either `Z` or `+00:00` is accepted on the wire. Reader dictionaries in open fixtures include the diagnostic fields returned by `read_reader`, including `attribution`, because no separate transformation into a wire reader is specified. |
| L183–186: “Ancestors follow the parent pid up to 4 levels, stopping at pid 1 or the first unreadable one.” | PID 1 is excluded. A parent with missing `stat` ends the chain. The spec does not say whether “stopping at pid 1” includes that ancestor. |
| L184–185: “Returns a dict with `proc_readable`, `start_time_before`, `start_time_after`, the reader fields (`pid, start_time, reused, uid, exe, comm, cgroup, cwd, ancestors`)” | On PID reuse, `start_time` retains the first observed start time; both observations are tested separately. The spec does not explicitly choose which observation supplies `start_time`. |
| L59–60: “ancestors are removed from the end, then `path` and `cwd` are cut from the left” | Remove ancestors only until the message fits, retaining the nearest ones. When shortening the path alone suffices, preserve cwd. Exact retained character counts are not prescribed or asserted. When cwd itself exceeds the limit, assert only suffix preservation and the byte bound, without choosing a minimum path length. |
| L201–205: “complete `coverage` messages for one version” and “concatenating the parts' lists gives back the sorted lists” | Empty coverage produces at least one part, permitting the empty version to be confirmed; the empty-input return value is not explicit. |
| L216–218: “on a new `gen` after an earlier one, a `gate_restart` and a closed gate `gap`” and “on a beat that ends an open silence, the closing `gap` record” | A restart during an existing silence closes the existing `gap_id`, alongside one restart record, rather than adding a second overlapping gap. R6 does not explicitly resolve this overlap; this interprets the requested “no double gap” case. |
| L127–128: “Every new `gen` ... with the old generation's last counters” and L170: “counts?” | `gate_restart.counts` is the four counter fields `opened`, `self_reads`, `answered`, `dropped` from the last beat. Nesting/names are not specified beyond the optional `counts` object. T5 also assumes `alive.counts.records_written`, based on L131: “`alive` carries ... records written”. These field-placement assertions require agreement with the implementer. |
| L225–229: “`failed` (which stops the replay, leaving that line and the rest)” and “retired ... only when `remaining` is 0” | After partial success the spool inode must remain, but acknowledged prefix lines may either remain or have been removed. Tests accept either policy and replay retained prefixes as conflicts. No checkpoint file/API is invented. |
| L143: “Homes are `community/<name>/` for each name in `members.json` → `members`” | The root harness uses the existing repository's `community/plaza/members.json`; r6 omits its parent directory. Temporary members follow the existing `session`/`events` shape, and both metadata and temporary homes/files are restored. Root tests are invoked as uid 1000 with sudo for individual privileged commands. |
| L112: “Database `ayllu_camera` on `arango-apacheta` (port 8529...)” | As in the repository's backup scripts, `arango-apacheta` is a Docker container, controlled with `sudo -n docker`. The database defaults to `http://127.0.0.1:8529`, overridable with `HAMUTAY_CAMERA_ARANGO_URL`. Optional `HAMUTAY_CAMERA_ARANGO_USER` and `HAMUTAY_CAMERA_ARANGO_PASSWORD` supply read-only credentials; the spec gives no credential location or login names. Status assertions query the specified collection over HTTP, since L156–158's CLI has no specified machine-readable format. |
| L239–240: “with the scribe stopped, never started, or with its queue full ... the gate starts and marks every home” | With the real scribe stopped, the harness creates absent, stale, and bound/full endpoints at the specified socket path, reproducing the three transport conditions. “Never started” is tested as an absent endpoint, not by erasing the installed scribe's history. Real fanotify marks are inspected through `/proc/<MainPID>/fdinfo`; no gate diagnostics API is assumed. |
| L241–244: “with both one queued and one delivered event” and “a failure in the middle of a multi-event batch” | There is no delivery barrier or fault-injection interface. A test-only Linux x86-64 `ptrace` helper stops after a fanotify `read` to prove delivery and injects `EBADF` on the second response `write`. It requires kernel `PTRACE_GET_SYSCALL_INFO`, a gate using `read`/`write` syscalls, and at least three already queued events in one read for T4. These are explicit harness dependencies, not mandated public camera interfaces. |
| L245–246: “20 concurrent readers ... in a loop for 60 s ... p99 below 2 ms and maximum below 50 ms” | Twenty threads act as independent concurrent callers, synchronizing their start. Measurements bracket `os.open` (including caller scheduling and permission wait), excluding close. The aggregate p99 uses nearest rank. A 68 s cleanup timer stops a stuck gate; it does not relax either latency bound. The spec does not choose threads vs processes or a percentile convention. |
| L247: “a new member's home is marked within 10 s and a coverage status appears” and L69–70: “there is no fixed bound, since the same part can be dropped again” | The mark has the exact 10 s bound. For test termination on a healthy channel the coverage-status observation allows 65 s, separately from marking. Other asynchronous status observations also allow 65 s, spanning one alive/flush interval. This is a harness timeout, not a claimed retransmission guarantee. T7 waits for a new alive after gate start to allow initial beats to reach the scribe; no public gate-beat observation API is specified. |

No policy is inferred for malformed messages, non-UTC inputs, invalid constructor
arguments, a generation change before any beat, or corrupt non-final spool lines.
Those cases have no r6 interface contract and are intentionally not asserted.

`test_pure.py` imports all eleven interfaces in fixture setup, so each collected
case fails at the absent module while `test_root.py` still reports its seven
default skips. Without `HAMUTAY_CAMERA_ROOT_TESTS=1`, even `sudo -n true` is not
executed. With the opt-in but without passwordless sudo, each root test skips.
